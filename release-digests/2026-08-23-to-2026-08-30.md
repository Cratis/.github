## Fixed

- **Chronicle** ([Release v16.41.0](https://github.com/Cratis/Chronicle/releases/tag/v16.41.0)): A constraint registered while its event sequence was already active was ignored for up to a second afterwards, so appends landing in that window bypassed it silently. The sequence now re-reads constraints on its first append after activation. This reaches any application that appends immediately after registering a constraint, not only the observer case it was found through. (#3868)
- **Chronicle** ([Release v16.41.0](https://github.com/Cratis/Chronicle/releases/tag/v16.41.0)): Pattern capture subscribed only at server startup, so an event store whose clients connected afterwards mined nothing at all until the next restart. Capture now also subscribes when event types are registered. (#3867)
- **Chronicle** ([Release v16.41.0](https://github.com/Cratis/Chronicle/releases/tag/v16.41.0)): `CHR0024` reported a read-model mapping written as `[property: SetFrom<T>]` as having no mapping source. Both that spelling and the bare attribute on the parameter are honored at runtime; the analyzer read only the parameter.
- **Chronicle** ([Release v16.41.0](https://github.com/Cratis/Chronicle/releases/tag/v16.41.0)): The Workbench pattern scope selector showed its placeholder instead of the selected scope, while the views below it were already showing that scope's patterns.
- **Chronicle** ([Release v16.40.0](https://github.com/Cratis/Chronicle/releases/tag/v16.40.0)): Adding a projection to an event store with a large event log could take the application down. Registration awaited one job-step grain being created, prepared and started per event source, exceeded its response timeout, failed host startup, and the restart re-registered into the queue it was waiting on (#3869)
- **Chronicle** ([Release v16.40.0](https://github.com/Cratis/Chronicle/releases/tag/v16.40.0)): A reactor's handler was silently never invoked when the reactor also had a private helper whose first parameter was the same event type. Nothing was thrown and nothing was logged; only the missing side effects showed it (#3870)
- **Arc** ([Release v22.6.2](https://github.com/Cratis/Arc/releases/tag/v22.6.2)): `useIdentity` now hands back the details it promises. The default details were substituted only when the identity was explicitly unset, so an identity that resolved while carrying no details — `isSet` is true — passed `null` through to callers, even though the declared return type says `details` is a `TDetails`. That is exactly why call sites dereference it unguarded, and one `null` reaching one of them takes the whole page down: a signed-in user got a blank screen with a `TypeError` on the first property read after their backend restarted. The default now stands in whenever there are no details to give, without displacing real ones.
- **Arc** ([Release v22.6.1](https://github.com/Cratis/Arc/releases/tag/v22.6.1)): An observable query now removes documents that stop matching its filter. The change-stream `$match` narrowed every operation type by the observed filter, but that filter is rendered against `fullDocument` — the document *after* the change — so an update that moved a document out of the result set produced an event the pipeline discarded. `HandleChange` compounded it by only ever calling `Add` on an update. The result was an observable that could only grow: an observer watching "orders still open" was told when each order opened and never when it closed, and the stale rows survived until the client reconnected. (#2617)
