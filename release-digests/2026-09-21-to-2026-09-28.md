- **cli** ([Release v3.17.1](https://github.com/Cratis/cli/releases/tag/v3.17.1)): The `screenplay` MCP descriptor must be stdio, command `cratis`, with exactly `screenplay mcp` as arguments. Anything else is refused before any file is written, matching the rule the Pi bridge in Cratis/AI enforces.
- **cli** ([Release v3.17.1](https://github.com/Cratis/cli/releases/tag/v3.17.1)): `cratis ai status` flags a managed MCP entry whose launch command is not the allowed one.
- **Arc** ([Release v22.23.0](https://github.com/Cratis/Arc/releases/tag/v22.23.0)): `Policy` and `AuthenticationSchemes` no longer silently fall back to authentication-only checks. Unknown, ambiguous, malformed, or unsupported requirements fail closed; applications using previously ignored settings must register valid policies and schemes before startup (#2736).
- **Arc** ([Release v22.23.0](https://github.com/Cratis/Arc/releases/tag/v22.23.0)): Scheme-selected execution isolates the effective principal, tenant, and scoped services. Unsafe caller-supplied providers and identity-changing nested scheme calls are rejected rather than reusing services bound to another identity. Standalone Core does not support named authentication schemes (#2736).
- **Arc** ([Release v22.21.0](https://github.com/Cratis/Arc/releases/tag/v22.21.0)): `[Authorize]` and `[AllowAnonymous]` from `Microsoft.AspNetCore.Authorization` are enforced again on model-bound commands and read models when Arc is hosted on ASP.NET Core. Since v18.2.0 a model-bound artifact protected only with Microsoft's `[Authorize]` was open to every caller — over HTTP, over hub subscriptions and through direct pipeline execution — because the evaluators meant to honour it read Arc's same-named attributes instead (#2719)
- **Arc** ([Release v22.21.0](https://github.com/Cratis/Arc/releases/tag/v22.21.0)): Every authorization attribute on a declaration now applies. Previously only the first one found was evaluated, so a second, stacked requirement — `[Roles("Admin")]` together with `[Authorize(Roles = "Auditor")]` — was silently dropped
- **Arc** ([Release v22.21.0](https://github.com/Cratis/Arc/releases/tag/v22.21.0)): A declaration marked both `[AllowAnonymous]` and `[Authorize]`/`[Roles]` is always rejected as ambiguous. Previously it either threw or admitted anonymous callers depending on which evaluator was discovered first (#2714)
- **Screenplay** ([Release v4.15.0](https://github.com/Cratis/Screenplay/releases/tag/v4.15.0)): Preserve restricted file access during model replacement, moves, and rollback; refuse recovery that would overwrite unexpected external edits.
- **Arc** ([Release v22.19.0](https://github.com/Cratis/Arc/releases/tag/v22.19.0)): SSE subscribe and unsubscribe now verify that the caller owns the connection they name. The identity that opened the stream is captured once and compared on each control request; a mismatch returns 404, exactly as an unknown connection id does, so the endpoints never confirm another caller's connection exists. Previously a caller holding another connection's id could attach a subscription whose results were written into that caller's stream, or cancel their subscriptions (#2713)
